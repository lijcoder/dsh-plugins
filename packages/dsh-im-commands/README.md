# @lijcoder/dsh-im-commands

DeepSeek Harness 功能：**在即时通讯软件里用 `/` 命令查询 dsh 状态。**

与平台无关——收发都走接缝 [`@lijcoder/dsh-im`](../dsh-im)，被动回复沿用收到的那条消息，
不需要另配目标会话。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/list` | 按工作目录分组列出**当前进程里活着的顶层会话**：标题 + 运行状态 |
| `/help` | 按注册顺序列出所有命令 |

加一条命令就是在 `registerCommands` 里 `router.register({ name, summary, run })`，
`run` 返回一个 `ImDocument`；`/help` 会自动带上它。

## 展示：一级目录、二级会话

`/list` 产出的是一张表，首列是工作目录，**空首列表示与上一行同目录**：

```ts
{ columns: ['目录', '会话', '状态', 'sessionId'],
  rows: [ ['~/work/a', '修复登录超时', '🏃 运行中', 's2'],
          ['',         'Greeting',     '💤 空闲',   's1'],
          ['~/work/b', '随手问问',     '💤 空闲',   's3'] ] }
```

同目录内**运行中的排在前面**，其余保持注册顺序。到了通道那边，默认渲染成带空首格的**真表格**：

```
## 🖥 DSH 会话（3）

| 目录 | 会话 | 状态 | sessionId |
| --- | --- | --- | --- |
| ~/work/a | 修复登录超时 | 🏃 运行中 | s2 |
|  | Greeting | 💤 空闲 | s1 |
| ~/work/b | 随手问问 | 💤 空闲 | s3 |
```

空首格就是 `ImTable` 的**分组约定**（与上一行同组），支持表格的通道照原样渲染。

声明 `tables: false` 的通道（纯文本 webhook 之类）会自己降级成「加粗路径 + 引用块」，
功能侧不用改——降级是通道的事：

```
**~/work/a**
> 会话：修复登录超时 · 状态：🏃 运行中 · sessionId：s2

> 会话：Greeting · 状态：💤 空闲 · sessionId：s1
```

## 交互约定

- 群聊里机器人只有被 @ 才会收到回调、正文带 `@机器人` 前缀，**解析前先剥掉**；
- 不是命令的普通聊天不回复；
- 未知命令回一条带 `/help` 的提示；
- 命令抛错回 `⚠️ 命令 /x 执行失败` + 原因（命令台是交互面，静默失败等于「没反应」，没法排障）。

## 配置

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `channel` | 唯一通道时自动选中 | 用哪个通道收发（注册了多个时必填） |

## 已知限制

- **通道在挂载时立即解析**（不像通知功能那样惰性取）：被动回复必须先在通道上订阅
  `onMessage`，订阅不到就收不到任何命令。所以缺通道是启动期错误——这也是组合包必须把
  通道行排在功能行之前的原因。
- 本包是**纯库，不能单独装**（不带 `dsh.bundle`）；装组合包
  [`@lijcoder/dsh-im-wecom-profile`](../dsh-im-wecom-profile)。
- `/list` 只覆盖**当前进程内存里**的会话：没加载进内存的历史会话、其它进程（单独跑的
  headless 等）看不到。

## 验证

```sh
pnpm --filter @lijcoder/dsh-im-commands test
```

11 个用例：命令解析（含 `@提及` 前缀、非命令输入）、未知命令与抛错回复、注册顺序生成
`/help`、`/list` 的分组与排序、无会话时的提示、无工作目录分组。
