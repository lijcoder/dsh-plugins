# @lijcoder/dsh-im-commands

DeepSeek Harness 功能：**在即时通讯软件里用 `/` 命令查询 dsh 状态。**

与平台无关——收发都走接缝 [`@lijcoder/dsh-im`](../dsh-im)，被动回复沿用收到的那条消息，
不需要另配目标会话。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/list` | 按工作目录分组列出**当前进程里活着的顶层会话**：一个目录一张表，表里是会话 + 运行状态 |
| `/help` | 按注册顺序列出所有命令 |

加一条命令就是在 `registerCommands` 里 `router.register({ name, summary, run })`，
`run` 返回一个 `ImDocument`；`/help` 会自动带上它。

## 展示：一个目录一张表

`/list` 产出的是一组表，**每个工作目录一张**，目录名当表标题，表里是这个目录下的会话：

```ts
tables: [
  { title: '~/work/a', columns: ['会话', '状态', 'sessionId'],
    rows: [ ['修复登录超时', '🏃 运行中', 's2'],
            ['Greeting',     '💤 空闲',   's1'] ] },
  { title: '~/work/b', columns: ['会话', '状态', 'sessionId'],
    rows: [ ['随手问问', '💤 空闲', 's3'] ] },
]
```

拆表而不是「一张大表 + 目录列」：目录名长短不齐，塞在列里既占宽度，又要靠「空首格 = 与
上一行同组」表达分组。拆开之后每张表都只剩真正会变的信息。表之间按目录名排序，
**同一张表里运行中的排在前面**，其余保持注册顺序。

标题保持「`🖥 DSH 会话（总数）`」原样，**括号后追加运行数**——打开企微第一眼就知道
现在有没有事在跑：

| 情况 | 标题 |
| --- | --- |
| 有会话 | `🖥 DSH 会话（3）· 🏃 2 个运行中` |
| 一个会话都没有 | `🖥 DSH 会话`（不产出表格，正文一句「当前没有活着的会话。」） |

企微这条通道支持标准 markdown 表格，所以上面那张在企微里就是**真表格**：

```
## 🖥 DSH 会话（4）· 🏃 2 个运行中

**~/work/deepseek-harness**

| 会话 | 状态 | sessionId |
| --- | --- | --- |
| 排查 loader 竞态 | 🏃 运行中 | s3 |

**~/work/dsh-plugins**

| 会话 | 状态 | sessionId |
| --- | --- | --- |
| 重构 IM 接缝 | 🏃 运行中 | s2 |
| 修复 /list 展示 | 💤 空闲 | s1 |
```

声明 `tables: false` 的通道（纯文本 webhook 之类）自己降级成「加粗目录 + 逐行引用块」，
功能侧不用改——降级是通道的事：

```
## 🖥 DSH 会话（2）· 🏃 1 个运行中

**~/work/a**

> 会话：修复登录超时 · 状态：🏃 运行中 · sessionId：s2
> 会话：Greeting · 状态：💤 空闲 · sessionId：s1
```

## 交互约定

- 群聊里机器人只有被 @ 才会收到回调、正文带 `@机器人` 前缀，**解析前先剥掉**；
- 不是命令的普通聊天不回复；
- 未知命令回一条带 `/help` 的提示；
- 命令抛错回 `⚠️ 命令 /x 执行失败` + 原因（命令台是交互面，静默失败等于「没反应」，没法排障）。

## 配置

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `channel` | 唯一通道时自动选中 | 用哪个通道收发（注册了多个时必填） |

## 已知限制

- **入站从接缝订阅**（`ctx.im.onMessage`），挂载时**不要求通道已就位**：loader 先
  `await import` 模块再创建 fiber、且不等激活，所以行序不决定激活顺序——曾经在挂载时
  解析 `ctx.im.channel('wecom')`，结果 `/list` 让整个 profile 起不来。现在通道后到也收得到。
- 配了 `channel` 就只收那个通道的消息；没配则全收（回复走 `message.reply` 原路返回，
  不存在发错地方的问题，所以这里比出站宽松）。
- 本包是**纯库，不能单独装**（不带 `dsh.bundle`）；装组合包
  [`@lijcoder/dsh-im-wecom-profile`](../dsh-im-wecom-profile)。
- `/list` 只覆盖**当前进程内存里**的会话：没加载进内存的历史会话、其它进程（单独跑的
  headless 等）看不到。

## 验证

```sh
pnpm --filter @lijcoder/dsh-im-commands test
```

15 个用例：命令解析（含 `@提及` 前缀、非命令输入）、未知命令与抛错回复、注册顺序生成
`/help`、`/list` 的拆表与排序（含「同目录不按运行状态拆成两张表」）、无会话时的提示、
无工作目录分组。
